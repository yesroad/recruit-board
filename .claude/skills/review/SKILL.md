# Review Skill

구현 직후 검토자를 호출해 지적을 모은다.
**승인 없이 고치지 않는다.** 지적을 모아 보여주고, 사용자가 지정한 것만 수정한다.

## Workflow

1. **대상 확인.**
   `git status --porcelain` 과 `git diff` 로 이번에 바뀐 파일을 파악한다.
   변경이 없으면 "검토할 변경 없음" 안내 후 종료.

2. **code-reviewer 호출.**
   `code-reviewer` 에이전트를 Agent 도구로 호출. 출력은 `.claude/_workspace/review/01_review.md`.

3. **a11y 필요 판정.**
   변경에 `.tsx`·`.jsx` 컴포넌트나 이벤트 핸들러가 포함되면 `a11y-checker` 에이전트를 Agent 도구로 호출한다.
   훅·유틸·설정·문서만 바뀌었으면 건너뛰고 그 판단을 한 줄로 알린다.
   출력은 `.claude/_workspace/review/02_a11y.md`.

4. **통합 보고.**
   두 결과를 심각도 순으로 합쳐 보여준다. `P0` → `P1` → `P2`.
   각 항목의 **`파일:줄` 과 재현 방법을 줄이지 않고 그대로 노출한다** — 사용자가 이걸 보고 직접 확인한다.

5. **마무리 안내.**
   "재현해서 확인한 항목을 알려주시면 그것만 고칩니다. 고친 뒤 `/review` 로 재검토하세요."
   지적이 없으면 "발견 없음" 을 그대로 전한다. 억지로 만들지 않는다.

## 작업 원칙

- 두 에이전트를 순서대로 호출한다. a11y는 필요할 때만.
- **승인 없이 고치지 않는다.** 무엇을 고칠지는 사용자의 판단이며, 그 판단이 PROMPTS.md의 재료다.
- 요약하되 재현 방법은 원문 그대로 둔다. 그것이 사용자가 실제로 쓸 정보다.
- 재검토하면 `.claude/_workspace/review/` 를 덮어쓴다.

## 커밋 게이트에 넣지 않는 이유

`lint` 와 `test-unit` 은 `commit-msg` 가 자동으로 돌리지만 이 스킬은 그러지 않는다.
리뷰 지적은 **재현하고 고칠 시간이 필요하고**, 그 결과가 `prompt-log` 의 재료다.
`prompt-log` 는 `commit-msg` 보다 먼저 돌므로, 리뷰를 커밋 직전에 두면 순서가 어긋난다.
